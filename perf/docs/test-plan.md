# 性能测试方案（上线前五阶段计划）

制定日期：2026-08-04。定位：对上汇报与对内执行的同一份底稿——阶段表看进度，盘点表看现状，gap 表看阻塞。
执行细节不在本文重复：摸底流程见 `baseline-runbook.md`，指标体系见 `metrics-theory-and-coverage.md`，看板读法见 `grafana-metrics-guide.md`，环境就绪见 `env-checklist.md`。

## 1. 五阶段计划

| 阶段 | 目标 | 退出条件（产出物） | 状态 |
|---|---|---|---|
| **0 · 就绪** | 环境/数据/账号/监控/目标负载五项就位 | env-checklist 全绿；**生产峰值流量画像**（每接口预期 TPS）与 **SLA 正式值**到手 | 🟡 约 60% |
| **1 · 摸底与基线** | 每个 P0 接口：拐点 K + 工作点 + 基线晋升 | 每接口 baseline 文件 + 容量表（K、标称容量、瓶颈层） | 🟡 约 30% |
| **2 · 达标验证** | 预估生产峰值 × 安全系数（1.5–2×）下 SLA 全绿 | 达标报告：verdict PASS × 3 轮稳态 | ⚪ 未开始（被阶段 0 的流量画像阻塞） |
| **3 · 组合与情景** | 混合流量（按生产画像配比）+ E2E lifecycle 链路 + 峰值日模拟 | mixed 场景达标；全链路延迟分解 | ⚪ 未开始（依赖 P0-W 与 P1c） |
| **4 · 极限与弹性** | stress 过载行为、spike 突发恢复、soak 8h+ 无衰减 | 三份专项结论：崩塌形态 / 恢复时间 / 无泄漏证明 | ⚪ 未开始（profile 已备） |
| **5 · 门禁与回归** | 上线 go/no-go 标准 + 长效回归机制 | go/no-go 清单签字；CI 定时回归运行 | ⚪ 未开始 |

推进原则：**阶段 1–2 按接口滚动**，不齐头并进——create/query 先行推到阶段 2，其余 P0 接口跟进；每阶段产出都是"可供上线决策的证据"，不是测试内部文档。

## 2. 现状盘点（截至 2026-08-04）

**平台层（100%）**：零依赖工具链（run.sh + k6）、错误三分类判定（业务口径，HTTP 200 的业务失败可见）、成功样本 SLA 口径、基线自动对比标红、双看板（对账区精确 + 趋势/容量/服务端 U/S）、四份方法论文档。

**阶段 0（约 60%）**：监控串联已通（k6 与服务端同 Prometheus，CPU/DB 池面板就位）；身份池方案落地（差 20 账号审批）；数据纪律成文。缺：流量画像、SLA 正式值、存量数据量级确认、限流口径决策。

**阶段 1（约 30%）**：5 场景可跑（query/detail/risk-metrics/unread-count/create）；ladder 摸底两轮（发现并定位网关 per-user 限流；服务端 U 证据显示仍在线性区）。缺：拐点未真正到达、基线零晋升。

## 3. Gap 清单（按阻塞程度排序）

| # | Gap | 影响 | 责任侧 |
|---|---|---|---|
| 1 | **生产峰值流量画像未知** | 阶段 2"达标"无分母，阶段 3 配比无依据——最硬阻塞 | 业务方/架构师提供 |

## 4. 对上汇报框架

三句话主线：

1. **成果**：性能测试基础设施与方法论已完成并经实战校验——一条命令出可信结论，第一周即拦下网关限流风险；
2. **定位**：正处在"平台建设"转入"验证执行"的节点，五阶段计划已定，当前卡在阶段 1–2 之间；
3. **要输入**（风险语言）：往下推进必须由业务侧给两个数——**生产峰值流量画像**与**正式 SLA**。没有它们，我们能证明系统"能扛多少"，无法证明"够不够用"——而后者才是上线决策需要的结论。

**Asks（四项，全部是协调不是采购）**：① 流量画像；② SLA 校准会；③ 20 个压测账号审批；④ 限流口径决策。

汇报材料：`perf-platform-showcase.html` + 本文 §1 阶段表（标红绿灯）。领导看进度条与阻塞点，不看测试细节。
